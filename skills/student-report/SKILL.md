# 학생 학습 리포트 — 강인한 국어 작성 기준

이 기준은 academy-manager 앱의 리포트 엔진과 같은 철학이다. 앱 밖에서 손으로 쓰는 분석·보고서도 같은 품질이 나와야 한다. 세부는 references/를 읽는다:

- `references/작성-원칙.md` — 품질 원칙 전체, 좋은/나쁜 문장 예시, 금지 목록
- `references/청자와-형식.md` — 청자 4종별 톤·안전선, 보고서 유형별 구조(종합 보고서·질문 분석·주간 진단·운영 브리핑)

## 핵심 원칙 (요약)

1. **데이터 기반** — 모든 평가는 구체 수치·날짜·사건을 근거로. "잘하고 있어요" 같은 추상 칭찬 금지. ✗"출결이 좋습니다" → ✓"출결 95%(20회 중 결석 0, 지각 1)".
2. **관통 스토리 1개** — 종합 평가는 항목 나열이 아니라 이번 기간을 하나로 꿰는 서사 3~4문장. 개별 항목은 각자의 섹션에.
3. **밀도** — 모든 문장이 새 정보를 담는다. "꾸준히 노력하는 모습이 인상적입니다" 같은 빈 문장 1개가 보고서 전체 신뢰를 깎는다. 채울 내용이 없으면 짧게 끝내는 것이 정답 — 분량은 상한일 뿐이다.
4. **반복 절대 금지** — 한 사실은 한 곳에서만. 같은 수치·진단이 두 섹션에 나오면 한 곳만 남긴다.
5. **강점·약점 균형** — 무조건 긍정도 무조건 부정도 신뢰를 잃는다. 각각 수치 근거와 원인 가설을 붙인다.
6. **처방은 실행 단위로** — 반드시 빈도·시간·분량 명시("월·수·금 20분씩 비문학 지문 1개 구조도 그리기"). 학원에 실제 있는 수업·클리닉에 연결하고, 없는 프로그램·교재를 지어내지 않는다. 집에서 혼자 못 하는 처방 금지.
7. **개별성** — 학생이 스스로 남긴 질문, 클리닉 총평, 실제 과제명·날짜를 인용해 "이 학생만의 이야기"를 만든다. 개별 근거가 없으면 일반론으로 읽힌다.
8. **빈약하면 솔직히** — 데이터가 부족하면 지어내지 말고 "아직 이번 기간 데이터가 충분하지 않아 다음 보고서에서 더 정확히 분석하겠습니다"라고 쓴다. 추측은 "관찰이 더 필요합니다"로 표시.
9. **자연스러운 한국어** — 번역투("~에 대해", "~를 통해", "~적인 부분") 금지, 빈 강조어("매우", "정말") 금지, 같은 종결어미 3문장 연속 금지, 단문 위주.

## 청자 구분 (요약 — 상세는 references/청자와-형식.md)

| 청자 | 톤 | 핵심 안전선 |
|---|---|---|
| 학부모 | 따뜻하고 신뢰감 있는 격식체(~습니다) | 다른 학생 비교 금지, 내부 메모 원문 인용 금지, 가정에는 습관·환경·격려만 부탁(학습 내용 지도는 학원 몫) |
| 학생 | 정제된 격식체(~합니다/~해 보세요), 담백 | 반말·느낌표·응원단 톤 금지, 등수는 경쟁 압박 최소화 |
| 강사 | 전문적·간결·수치 중심 | 실무 진단 위주, 친근한 존댓말 가능 |
| 원장 | 짧고 단정적, 모든 주장에 수치 | "관리가 필요합니다" 같은 무엇·어떻게 빠진 문장 금지 |

## 항상 금지

- 학생 본명 외 **다른 학생 이름 언급·비교 금지**.
- 의학·심리 진단명(ADHD, 학습장애 등) 금지. 성격·의지 단정("게으르다") 금지. 임상 말투("처방", "○○형 — ○○ 훈련 필요") 지양.
- 학부모·학생 문서에 **'AI'·'인공지능' 표기 금지** — 학생 질문은 "스스로 남긴 학습 질문"으로, 학원의 지도 활동으로 서술.
- 학부모 이름 호명 금지 — "○○ 학생 학부모님"으로.
- 점수 단위 혼동 금지 — 만점 100이면 "90점", 아니면 "12/15점"처럼 분모 명시. %와 점을 섞지 않는다.
- 수강료·게이미피케이션(XP·레벨)은 학습 보고서에 넣지 않는다.
- 학원의 관리 의지 언급("다음 주부터 ○○ 클리닉을 신청해 드리겠습니다")은 전체에서 딱 1회 — 반복하면 영업 문구가 된다.

## 내기 전 자가 점검

1. 같은 수치·표현이 두 군데 이상 등장하는가 → 한 곳만 남긴다.
2. 종합 평가·강점·보완점에 숫자가 하나도 없는가 → 실패, 데이터 근거를 넣는다.
3. 처방에 빈도·시간·분량이 없는가 → "주 3회 20분"처럼 실행 단위를 명시한다.
4. 정보 없는 빈 문장이 있는가 → 통삭제.

## academy-manager 개발 작업과의 관계

앱 코드를 고칠 때는 앱 안의 프롬프트(server/routes/reports.js, weeklyStudentDiagnosis.js 등)가 기준(SSOT)이다. 이 스킬은 앱 밖에서 — 내보낸 데이터 분석, 일회성 보고서, 대화 분석 — 같은 품질을 내기 위한 것이다. 둘이 어긋나면 앱 쪽 기준을 따르고 이 스킬을 갱신한다.
